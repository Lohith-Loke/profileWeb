You are given a directed acyclic graph of `n` nodes numbered from `0` to `n - 1`. It's represented by a 2D array `edges` of length `m`, where `edges[i] = [u, v, cost]` indicates a one-way communication from node `u` to node `v` with a recovery cost of `cost`.

Some nodes may be offline. You are given a boolean array `online` where `online[i] = true` means node `i` is online. Nodes `0` and `n - 1` are always online.

A path from `0` to `n - 1` is valid if:

- All intermediate nodes on the path are online.
- The total recovery cost of all edges on the path does not exceed `k`.

For each valid path, define its score as the minimum edge cost along that path.

Return the **maximum** path score (i.e., the largest **minimum**-edge cost) among all valid paths. If no valid path exists, return `-1`.

**Input:** `edges = [[0,1,5],[1,3,10],[0,2,3],[2,3,4]]`, `online = [true,true,true,true]`, `k = 10`

**Output:** `3`

## Explanation

<NetworkGraph nodes={postNodes} edges={postEdges} />

The graph has two possible routes from node `0` to node `3`:

- **Path 0 → 1 → 3**
  - Total cost = `5 + 10 = 15`, which exceeds `k` (`15 > 10`), so this path is invalid.
- **Path 0 → 2 → 3**
  - Total cost = `3 + 4 = 7`, which is ≤ `k`, so this path is valid.
  - The minimum edge cost along this path is `min(3, 4) = 3`.

There are no other valid paths, so the maximum score among all valid paths is `3`.

## Approach

Two observations drive the approach:

- We're maximizing a minimum — that's a strong hint to **binary search on the answer**.
- Among paths that respect that minimum, we still need the total cost to stay under `k` — a constraint that a **Dijkstra-style shortest-path search** can enforce directly.

### Step 1 — Bound the binary search

The answer (the maximum possible "minimum edge cost") can only be somewhere between the smallest and largest edge weight in the graph, so those become our search bounds:

```python
mincost = min(mincost, cost)
maxcost = max(maxcost, cost)
```

### Step 2 — Binary search template

Standard binary-search-on-answer scaffolding: for each candidate `mid`, check whether a valid path exists whose edges are all `>= mid`, and narrow the range accordingly.

```python
while l <= r:
    mid = (l + r) // 2
    if check(mid):
        ans = mid
        l = mid + 1
    else:
        r = mid - 1
return ans
```

### Step 3 — The check function

`check(mid)` answers: _is there a path from `0` to `n - 1` that only uses edges with weight `>= mid`, and whose total cost stays within `k`?_

This is a modified Dijkstra: edges below `mid` are skipped entirely (so the path's minimum edge is guaranteed to be `>= mid`), and we bail out early if the running cost of the path ever exceeds `k`.

## Code

```python
from collections import defaultdict
from heapq import heappush, heappop

class Solution:
    def findMaxPathScore(self, edges: List[List[int]], online: List[bool], k: int) -> int:
        # skip edges touching an offline node — they can never appear on a valid path
        graph = defaultdict(list)
        mincost = float("inf")
        maxcost = -float("inf")
        n = len(online)

        def checkPath(mid):
            # only edges with cost >= mid are allowed
            que = [(0, 0)]
            cost = [float("inf")] * n
            cost[0] = 0
            while que:
                pathcost, node = heappop(que)
                if pathcost > cost[node]:
                    continue
                if pathcost > k:
                    return False
                if node == n - 1:
                    return True  # reached the target within budget
                for nxt, ncost in graph[node]:
                    if ncost < mid:  # skip edges below the current threshold
                        continue
                    tcost = ncost + pathcost
                    if tcost >= cost[nxt]:  # not an improvement, skip
                        continue
                    cost[nxt] = tcost
                    heappush(que, (tcost, nxt))
            return False

        for u, v, c in edges:
            if not online[u] or not online[v]:
                continue
            graph[u].append((v, c))
            mincost = min(mincost, c)
            maxcost = max(maxcost, c)

        l, r, ans = mincost, maxcost, -1
        while l <= r:
            mid = (l + r) // 2
            if checkPath(mid):
                ans = mid
                l = mid + 1
            else:
                r = mid - 1
        return ans
```

### Complexity

- **Binary search:** `O(log(maxcost - mincost))` iterations.
- **Each `check(mid)` call:** a Dijkstra-style traversal, `O((n + m) log n)`.
- **Overall:** `O((n + m) log n · log(maxcost))`, where `n` is the number of nodes and `m` is the number of edges.
